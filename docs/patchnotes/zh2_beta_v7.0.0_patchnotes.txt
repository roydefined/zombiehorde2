New features
------------------------------------------------

* * New human start item system * *
Humans can now receive items at the start of a round through a new configurable system. This replaces the hardcoded 50% chance of a fire grenade, and maps giving flares through their own scripts.
Start items are defined in a new `HumanStartItems` block in `ZHMODDEF` lumps, and maps can define their own in their `ZHMAPDEF` entry. A map item overrides a mod item with the same name, allowing maps to change or disable it.
Each item has an `Amount` and a list of `Rule` entries (`MaxPlayers`, `Chance`). The first rule matching the number of humans determines the percentage of humans that receive the item, otherwise `DefaultChance` is used. An optional `PlayerCanReceiveScript` can exclude players, for example to only give an item under certain conditions.
Items are given one second after the zombie pick. By default, humans can also receive them early as soon as they spawn. Server hosts can turn this off with `sv_zh2_humanstartitemdistribution`.
Players who received an item on recent maps have a lower chance of receiving it again. Server hosts can set how many maps are remembered with `sv_zh2_humanstartitemhistory` (default 3, 0 disables it).
The fire grenade now uses this system: 100% of humans with up to 10 humans, 70% with up to 20 and 50% with up to 40.
Additionally various maps that previously gave a flare to every player now uses this system. ZM03 specifically provides this using a condition.

Map changes
------------------------------------------------

* * Flares are now given through the human start item system * *
Maps that gave every human a flare through their own scripts now use the new `HumanStartItems` block, with the same rules as the fire grenade. Only a portion of the humans receive a flare, based on the number of humans.
Affected maps: ZE08, ZE16, ZE18, ZE32, ZM01, ZM02, ZM03, ZM04, ZM05, ZM06, ZM19, ZM22, ZM24, ZM26 and ZM04M.
ZM03 still only gives flares when the map plays at night, which is handles with the conditional feature.

- [ZE04]:  Fixed an invalid player id error being logged for every dead player when the final resist starts.

API changes (Could contain breaking changes for mappers. Make sure to check this list for migrations)
------------------------------------------------

* * Renamed several `#define` names for naming consistency * *
Various `#define` names across the core mod and library smashed multiple words together without any separation (e.g. `EVENTSPREFIXKEY`), or used inconsistent casing.
These have all been renamed to consistently use `UPPER_SNAKE_CASE`, with words separated by underscores. Established compound terms that already read clearly (e.g. `HUDID`, weapon names like `SHOTGUN`/`RIOTGUN`, `AMBIENTWEATHER`) were intentionally left as-is.
See `zh2_beta_v7.0.0_define_renames.txt` in this same folder for the full list of old -> new names. If your map directly references any of them, update it to the new name.

* * Cvar getters now use a new namespace and follow a consistent naming convention * *
Every cvar function in the library and core now follows the same shape through a new system that ensures this consistency. This includes two major changes to cvars.
Firstly, cvars now reside in a new `CVar` namespace instead of being in `ZH2Game`. Secondly, the naming has been changed to match in consistency. Server cvars are now named `GetSv{Name}()`, client cvars are named `GetCl{Name}ByPlayerId(int)`, `GetCl{Name}ByConsolePlayer()` or `GetCl{Name}()`.
Notably with the new names, cvars now differ based on whether they target the server or a client. Secondly, this improvement also exposes two more cvars for clients, in order to get a value by a specific player, or by the console player. Some cvars already had this requirement, so it only made sense to properly support it.
The cvars are now all also publicly available, providing a strict-typed way to get the value of a setting.
For more information, see `zh2_beta_v7.0.0_cvar_function_renames.txt` which contains a full list of renamed cvars and their new name.

* * Actor-specific ACS moved out of maps into the core code * *
Several actors had their DECORATE-callable ACS logic hardcoded as numbered scripts directly in their home map's own ACS source. This meant the monster only worked correctly on the one map it was originally written for, and would break (or silently do nothing) if placed on any other map.
This logic has been moved into the new `zh2legacy`/`zh2modern` monster/decoration libraries as named scripts, always loaded by default to ensure the actors retain their behavior outside of the maps they were made for.
Affected actors: Weegee (ZE25), Comets (ZE20/ZE20B/ZM16/ZM25), Kameleon (ZM18/ZM16/ZM25), Ravishing, White Face/ImScared, Soulsphere (all ZM09) and Angel (ZM06M).
Genuinely map-specific orchestration (spawn sequences, stats tracking, hate/target direction) was intentionally left on the map, since it only ever runs there and add a layer of opinionated behavior best left for the map to decide.

CVars
------------------------------------------------

New CVars:
- `sv_zh2_enabledeathcam`: turns the death camera on or off for all players on the server. Enabled by default.
- `cl_zh2_enabledeathcam`: turns the death camera on or off for yourself. Enabled by default.

Some CVars have been renamed to match the conventions introduced with the cvar rework.
- `sv_zh2_ze11_enablefrozenteleporting` -> `sv_zh2_ze11enablefrozenteleporting`.
- `cl_zh2_ze14_enabledynamiclights` -> `cl_zh2_ze14enabledynamiclights`.
- `cl_zh2_zm14_enabledynamiclights` -> `cl_zh2_zm14enabledynamiclights`.
- `cl_zh2_enabledamagefeedbackmarkers` -> `cl_zh2_damagefeedbackmarkershowtype`.
- `cl_zh2_enabledamagefeedbackcounters` -> `cl_zh2_damagefeedbackcountershowtype`.
- `cl_zh2_enabledamagefeedbacknumbers` -> `cl_zh2_damagefeedbacknumbershowtype`.

The map-specific CVars are now limited to their valid range. A value outside the range now uses the nearest valid value.
Previously most CVars would enforce a default if out of bounds on the map-side.
This is now no longer the case, instead clamping the value within bounds.
- `sv_zh2_ze26flow`: 0 to 2.
- `sv_zh2_zm06event`: 0 to 3.
- `sv_zh2_ze12mflow`: 0 to 3.
- `sv_zh2_ze13mflow`: 0 to 3.
- `sv_zh2_zm06mevent`: 0 to 4.
- `sv_zh2_zm31mevent`: 0 to 3.
- `sv_zh2_zm31meventtics`: 350 to 21000. Before, any value of 1 or greater was accepted.

Other mod changes
------------------------------------------------

- Renamed several internal library and core source files/folders for naming consistency (e.g. `afkprevention` -> `afk_prevention`, `translucentallies.acs` -> `translucent_allies.acs`, `prepostscript.acs` -> `pre_post_script.acs`). This is internal only and does not affect maps.
- Added `zh2modern` and `zh2legacy`, matching `zh2lib`/`zh2game` structure-wise, giving the modern/legacy map-pack-specific cvars typed getters instead of raw `GetCVar`/`GetUserCVar` calls scattered across the map scripts.
- Fixed an issue with ZM09's soulsphere/ghouldemon dealing wildly excessive melee damage (effectively an instant kill) instead of its intended small damage amount to humans (or large, but survivable, damage to zombies) to to an invalid cast.
- Added two options to the debug menu, which log the parsed human start items and the human start item history of every player.
- Fix issue with the core's LOADACS lump not actually working. This was never noticed before because the mod doesn't use autoloading yet, and maps always loaded the code themselves.
- Fix `sv_zh2_minimumclientcount` not properly enforcing a minimum of 2 internally.
- The deathcam is now disabled when loading `docs/classicmode.cfg`.
- Fix the classic shotgun not being able to fire mid-reload.

Repository changes
------------------------------------------------

- `compile_maps.py` now also includes the new `ZombieHorde2Modern`/`ZombieHorde2Legacy` ACS source folders, so maps in those packs can reach the new cvar getters.
- Extended the VSCode workspace structure and PubDoomer profiles to properly support the new modern/legacy ACS files.
- `build_project.py` now also compiles the new `zh2legacy`/`zh2modern` libraries.
