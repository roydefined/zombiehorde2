New features
------------------------------------------------

 * * Identify player improvements * *
Improvements have been made tot he identify player system!
Server owners can now manage the feature globally with a new cvar `sv_zh2_identifyplayers`. By setting it to `false` you can turn it off.
Clients now have two new additions to the identify player feature.
First of all, enabling it can now optionally be based on the player's specie. CVar `cl_zh2_identifyplayers` now supports two more values indicating if we enable it for the same species, or other species specifically.
Secondly, players can now also manage what to show by configuring `cl_zh2_identifyplayertype`. With this CVar you can configure if you want to show names, species, or both.
This puts the feature more in line with new features in general and provides more control to players to configure it exactly how they want.

 * * HUD improvements to the ammo and counters * *
The HUD has been improved and now shows new graphics for the weapon ammo display and the counters.
The weapon ammo display has been shown some love with a new background rendered for the ammo when the weapon has anything to show.
Additionally, weapons with secondary ammo support draw another box to support this ammunition. This currently only applies to the riot shotgun.
The counters used for general human and zombie count and the kills and infections count have also been updated.
The counters have been moved, and the human and zombie counters can now be found underneath the player HUD part showing health, keys and other things.
The kills and infections have been moved above the weapon ammo counter, fitting the new background that was also added as mentioned above.
Additionally, all coutners now support a new background and font fitting to them, combining everything together into a neat display.

API changes
------------------------------------------------

 * * New game block in MAPDEF lumps * *
Maps can now define a new game block in which configuration for the general game can be configured.
This block is purely serverside and serves as a way for maps to configure specific game rules.
In this case it was added for configuring zombie teleports, but more will appear in the future.

 * * Extended support for zombie teleport API * *
More support has been added for the zombie teleport system, giving mappers more control over how their map supports it.
The system still provides the default zombie teleport spots, but you can now extend this with different sets that can be enabled conditionally.
Furthermore you can now also control if teleporting is enabled as a whole, and you can configure the maximum allowed teleports allowed on your map.
The maximum amount overrides the cvar value defined by the server, and you can also unset this if you want to revert back to the cvar value.
The new API exposes numerous functions that mappers can use to control the zombie teleport system to their taste:
- `void SetCurrentZombieTeleportSpotTid(int tid)`
- `int GetCurrentZombieTeleportSpotTid()`
- `void SetZombieTeleportingEnabled(bool enabled)`
- `bool GetZombieTeleportingEnabled()`
- `int GetInitialZombieTeleportSpotTid()`
- `void SetOverrideMaxZombieTeleports(int value)`
- `void UnsetOverrideMaxZombieTeleports()`
- `int GetMaxZombieTeleports()`
Lastly, lump reading has been extended and the new game block allows you to set the following things:
- The current zombie teleport tid to use.
- Whether teleporting is enabled in general (this can also disable the default behavior of it being on if you have spots with tid 0).
- The maximum number of allowed teleports.

 * * New slots and functions in safety system * *
The safety system has been extended with a new slot feature. This allows you to mark players as safe in individual slots.
This improves maps that have more than 1 safezone with the ability to now use the safety API for these other safezones.
Maps default to slot 0 when you place a player into the safezone, but you can use up to 16 slots for your map.
As an added bonus, safety slots can now be marked as "hidden". This will make slots not emit an obituary to players, nor will it show up on the HUD.
Making a safety slot hidden is very useful when you make a zone that is considered safe against something, but you don't want to show this (e.g. an intermediate room that players walk through).
The following functions were modified for this feature:
- KillUnsafePlayers, now allows you to specify a slot that is considered safe. Defaults to -1 which means any safezone is safe.
- SetIsSafe, SetPlayerIsSafe, GetIsSafe and GetPlayerIsSafe, also allows you to specify a slot.
The following new functions were added:
- GetIsSafeAny and GetPlayerIsSafeAny - Returns true if the player is safe in any slot.
- SetAllPlayersSafe, SetAllHumansSafe and SetAllZombiesSafe, which works similar to SetIsSafe and SetIsPlayerSafe, but instead marks all players as safe/unsafe.

 * * New kill functions * *
Mappers can now use two new functions in the Game namespace: `Kill` and `KillPlayer`.
These two functions simplify killing players by providing an easy-to-use function instead of setting up your own damage function.
Additionally, the damage modifier is an optional parameter, defaulting to MOD_UNKNOWN, or "unknown".

Other changes:
- Removed LogMessageLevel from the list of externed functions of the Logger namespace.
- `Music::SetMusic` has been renamed to `Music::PlayMusic` to better reflect the fact it plays the music, rather than just sets it.
- The ZH2 library has had multiple namespace renamed with a refactor in its folder structure. Many namespaces are no longer prefixed with `Lib` as code and include conflicts no longer exists.
- Added a new sound sequence that is completely silent.
