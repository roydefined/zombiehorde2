New features
------------------------------------------------

* * Mod split into separate packages * *
Zombie Horde 2 is no longer released as a single pk3. The mod is now split into separate packages that can be loaded independently.
These are `zombiehorde2` (core code and library), `zombiehorde2resources` (shared resources and Doom resources), `zombiehorde2legacy` (legacy maps) and `zombiehorde2modern` (modern maps).
Each package requires all packages before it, in that order. The supported combinations are core only, core + resources, core + resources + legacy, and all four.
Modern maps still use legacy assets, so modern requires legacy. This will be required until the resources are split or something changes that doesn't require it.
Server hosts must load every package they need, in this order too. If you fail to do so the server might show an error, or the mod will behave incorrectly.

* * Custom knockback rework * *
The custom knockback system has been reworked and is now enabled by default. Server hosts can access it with `sv_zh2_usecustomknockbackfeature`.
The previous system has been replaced as it did not work correctly, which was the reason this system was never used. It had too much effect on the game as a whole.
A better system is now in place which instead adjusts the engine knockback. This means the engine knockback now always applies.
When a player hits another player with a weapon, the mod replaces the engine knockback with its own when a player hits a zombie.
This has the benefit of not interfering with anything else. This was the biggest issue with the previous system, which is now resolved.
By default the custom knockback is the same as the engine knockback. Server hosts can scale it with `sv_zh2_usecustomknockbackmodifier` and `sv_zh2_customknockbackmodifiermultiplier`.
When you adjust the factors for players the mod shows a factor on the player's HUD, assuming you use the modern HUD. The legacy HUD does not show this.
Now also added is `sv_zh2_customknockbackverticalfactor` to bring back vertical knockback, as a factor of the horizontal knockback.
This system already existed before, but is now an optional toggle. Shots from above push down, shots from below push up. 0 turns it off.

* * Weapon slowdown feature * *
The handgun, chaingun and sniper have been changed and now uses a new system called slowdown. It replaces their knockback and now slow down zombies when hit.
These weapons had no real benefit from knockback and especially the chaingun is not really a useful weapon as it's outshined by the shotgun's knockback and sniper's damage.
The idea is to improve these using this system by giving them a whole new mechanic instead. The sniper is mostly an additional weapon added since knockback was also kind of pointless.
Each hit removes part of the zombie's speed. A hit that deals more damage slows down more, and a heavier zombie is slowed down less, just like knockback works.
It is also based on mass, but this is generally the same between all players so this doesn't do a whole lot currently. This might change in the future.
The slowdown is enabled by default. Server hosts can turn it off with `sv_zh2_useslowdownfeature`. Should they do this, these weapons use knockback again.
Slowdown and custom knockback can be toggled separately. When a weapon supports both, the slowdown is used instead and prioritized over the knockback.
Server hosts can scale the slowdown with `sv_zh2_usecustomslowdownmodifier` and `sv_zh2_customslowdownmodifiermultiplier`.
The HUD has also been updated to show this modified using a new graphic.

Map changes
------------------------------------------------

* * Modern map mapslot migration * *
Four modern maps have been migrated to a new mapslot to properly reserve the old mapslots for possible future modern reworks of these maps.
The modern maps that have been migrated did not represent the modern rework of the map (e.g. ZE07M was not actually a modern rework of ZE07).
The maps have been moved to a higher mapslot, and the old mapslots are now unused.
The following maps have been migrated:
- ZE07M "Island Escape" is now ZE33M.
- ZE08M "Military Base Escape" is now ZE34M.
- ZM07M "The Warehouses" is now ZM32M.
- ZM08M "Napalm in the Morning" is now ZM33M.

API changes (Could contain breaking changes for mappers. Make sure to check this list for migrations)
------------------------------------------------

* * Mod split into separate packages * *
Various definitions and assets were moved into the correct location to support the split into separate packages.
The ACS defines for the legacy keys and the egypt cash moved from the core `zh2game.h.acs` to the legacy `zh2legacy.h.acs`.
Map scripts that use them must now include `acs_source/zh2legacy.h.acs`. This breaking change is required or your map will no longer find them.
The Doom key replacements and the egypt cash are now part of the resources package. The Doom keys are listed under "Keys/Doom" in the map editor.

* * Weapon slowdown * *
ZHMODDEF weapon items have a new `Slowdown` property. A weapon with a slowdown slows zombies down instead of knocking them back, using the same formula as the engine's knockback.
ZHMODDEF powers have a new `SlowdownModifier` factor, which scales the slowdown of the player that has the power, similar to `KnockbackModifier`.

Other mod changes
------------------------------------------------
- Reworked logging to make the information log level more useful:
    - Reworked the log severities to improve how often the information log level is used.
      Previously almost all logging was debug, which made the console hard to read when looking for something specific, and information-level log messages were barely used.
      General logs that tell what happened in the game are now information. Logs that trace the individual steps of a system or log values for debugging stay debug.
      This should improve logging, and server hosts and clients can now set the minimum log level to information to properly reduce the debug-level logging noise.
    - The default log level is now information instead of debug. Any previous overrides for logging have been removed.
    - The logger now only reports a full buffer once per tic. Before this change it would report it with each added entry.
- The knockback multiplier icon is no longer drawn on the HUD when custom knockback is disabled.

Repository changes
------------------------------------------------

* * Mod split into separate packages * *
As part of the split into separate packages, changes have undergone in the repository.
The PubDoomer profile has now been updated to create separate packages as documented earlier, instead of merging all files together as one.
This is now done with all build profiles available.
`play_local_server.py` still loads all packages by default, but can now exclude packages with `--nomodern`, `--nolegacy` and `--noresources`.
Excluding a package also excludes every package that depends on it (e.g. `--nolegacy` won't load either the legacy nor modern package).
The config files you can load has also been changed because of this split.
The `host.cfg` file is still available as a base cfg, but you can now sideload two separate files based on the maplist loaded.
These are `maplist-legacy.cfg` and `maplist-modern.cfg`, for their respective maplists.
The `build_config_file.py` script now also correctly generates these new files, and the previous host template file + support for it has been deleted.
Other scripts have also been adjusted to account for the split, properly supporting the new structure.
The getting-started text of the mod package now describes the separate packages too.

- Improved the tooling within the project, filling gaps and making it easier to run the tools and catch issues.
    - `find_texture_duplicates.py` now correctly truncates lump names to 8 characters, so textures that have a longer name correctly get caught as duplicates.
    - Added `find_sprite_duplicates.py`, a tool similar to `find_texture_duplicates.py` that finds duplicate sprites (including rotations).
    - Added `validate_sprite_names.py` and `validate_texture_names.py`, two scripts that validate the naming of sprites and textures and report invalid names.
    - Added `find_lump_path_duplicates.py` as a way to find duplicate lumps based on relative paths.
    - Added `validate_build.py` as a master script to validate the project as a whole by invoking all validation scripts the project now has.
- Improved logging in the tooling:
    - Added a `--verbose` option for scripts that use the logging in the tooling, and improved the tooling in general to support verbose logging.
      If set, debug logging will be output. This means debug logging is now turned off by default.
    - `build_config_file.py`, `create_tag.py` and `play_local_server.py` now make use of the logging system.
- Improved `play_local_server.py`:
    - Fixed `sv_maxclients` not being set properly.
    - Now loads an optional `host-testing.cfg`, which applies extra parameters for testing. For now this is only `sv_maxclientsperip 64`.
    - Now loads all radio tracks unless otherwise specified.
    - Added a client count parameter. If unset, the script asks for the number of clients. It will open this many instances of Zandronum.
