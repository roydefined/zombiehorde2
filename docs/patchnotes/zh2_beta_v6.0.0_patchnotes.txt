New features
------------------------------------------------

* * New data sync callback system * *
The way data is synchronized between server and clients has been improved with a new callback system.
Previously the sync flow was scattered, but it has now been improved and a new event has been added that will be triggered whenever data is synchronized.
Clients will now trigger this event as soon as data is set, including offline where generally this synchronization is skipped.
This way there is now support for properly handling extra behavior when data has a finalize step, as has existed in various occasions.
Previously this meant having to write duplicate code, but this is now gone.
Additionally, sync data can now be debounced through buffers to reduce redundant work and traffic.
Instead of sending sync data immediately every time, the new buffer collects it and sends it more efficiently.
This behavior can be toggled with a setting to enable the new buffer, allowing hosts to opt in or revert to the previous behavior.
Additionally, the sync system now supports configuring delays to better control when synchronization happens.
A general sync delay can now be configured, and a separate initial sync delay can be set specifically for syncs on map start.
This way the whole issue of doing duplicate sync calls is now completely fixed.

* * Anti-SR50 system * *
A new system was added which aims to remove SR50 from the game.
This has always been a controversial topic. It's a mechanic that has existed for a long time.
However, it's not something that players consider when playing the game. Especially when it comes to new or casual players this system is not known.
I don't think SR50 has a place in a game where speed is important. With sprinting and varying other speeds at play, SR50 can make a big difference.
This system will reduce the player speed if the game detects multiple inputs combined, causing SR50.
In the event a server host does not want to remove SR50 from the game, they can still do so.
This system will come with a cvar which will turn it off.

* * Zombie leave compensation improvements * *
The system that handles zombies leaving a round has been expanded.
A leaving zombie will now cause the game to compensate other zombies based on their health.
The health of the zombie will be distributed amongst other zombies, and based on the health left the timer will also increase based on a factor of it.
This helps reduce situations where a round becomes significantly easier because a zombie suddenly leaves.
The amount of time added or health returned is configurable through a cvar and can be disabled entirely if desired.
Additionally, the system now supports optionally awarding a zombie kill to a human player if they dealt enough damage to the zombie before they left.
Server hosts can configure the required damage percentage through a cvar.
If multiple players qualify, the player who dealt the most damage will receive the kill and any associated rewards.
This helps ensure players are still rewarded when a zombie leaves after taking significant damage.

* * Zombie bans on leaving the round * *
Additional to the compensation changes, the game now also supports banning a zombie if they were to leave mid-game.
Zandronum now supports bannign through ACS with the cvar `sv_maxacsbanduration`.
Server hosts will be able to enable banning through this cvar, or disable it by setting the vlaue to 0.
The game also respects this value and banning a zombie will happen based on the time provided by `sv_maxacsbanduration`.

Repository changes
------------------------------------------------
- The repository has more Python files for managing the project:
    - A Python script that handles the compression of sounds using ffmpeg.
    - A Python script that handles the compression of graphics using oxipng.
    - A Python script that handles the creation of tags on the current commit based on the current version.
    - A Python script that handles the updating of the mod version across multiple files to avoid having to updating multiple locations.
- Moved contents used as templates from the build/ folder to the templates/ folder.
- Renamed the 'pk3/lib' folder to 'pk3/libraries/ZombieHorde2Lib' and updated the project to point to its new location.
- Added a version.txt file which will contain the current version of the mod. One of the new Python scripts will use this file as reference when updating.
- Builds made of the mod through PubDoomer in this project are now in lowercase rather than PascalCase.
